# CSDN 同步助手公开资料研究

研究日期：2026-10-26。目标是理解产品流程并指导 yuzgeo 的独立实现。

## 已确认的产品行为

| 环节     | 公开资料说明                                                     | 对 yuzgeo 的意义                                                       |
| -------- | ---------------------------------------------------------------- | ---------------------------------------------------------------------- |
| 文章来源 | 从 CSDN 创作工作台或历史文章进入同步流程，自动预填文章           | 在线文章的正文和图片已有来源；本地 Markdown 还需要先解决文件与图片读取 |
| 登录     | 扩展复用目标平台在浏览器中的登录态                               | 保留浏览器端适配器，先展示账号状态，再允许同步                         |
| 排版     | Markdown 按平台转换；公众号使用富文本，代码块可转图片            | 一份正文需要分别适配，不能只把同一段 HTML 发送给所有平台               |
| 图片     | 官方明确说明会自动上传图片                                       | 应继续实现图片转存，无需因此退回纯文字产品                             |
| 结果     | 提供同步进度、历史、失败原因和重试，成功后可打开目标编辑器       | 每个平台独立反馈结果，异常必须可见                                     |
| 草稿     | 默认保存草稿；当前官网称部分平台可显式选择发布，MCP 始终保存草稿 | yuzgeo 维持当前只创建草稿的边界即可                                    |

依据：[官方操作手册](https://blog.csdn.net/blogdevteam/article/details/159927751)、[官方功能页面](https://sync.csdn.net/)。上述为官方公开的行为说明，并非对全部平台的实测保证。

## MCP 的公开接入方式

官网提供 `csdn-article-sync-mcp`，由本机 AI 客户端通过 `npx` 启动，走 stdio；扩展设置中启用 MCP 并复制连接 Token。配置示例使用 `CSDN_PUBLISH_MCP_TOKEN` 和 `CSDN_PUBLISH_MCP_PORT`，默认端口为 3721，并说明修改端口时应同步修改扩展 WebSocket 地址。

官网给出的调用流程是：先检查登录状态与草稿、图片能力；提交标题及 Markdown / HTML 正文；使用同一任务键查询各平台结果。平台 Cookie 不提供给 MCP Server。MCP 不提供网页文章抓取或直接发布能力。

依据：[官网 AI / MCP 说明](https://sync.csdn.net/#mcp)。npm 元数据查询显示包版本为 1.0.1；本次未运行该第三方服务。

## 可借鉴的架构推断

结合上述行为，可采用以下独立实现路径。这里是工程推断，不代表已确认对方内部函数、接口或算法：

1. 将来源整理为标题、正文、封面、标签、图片引用。
2. 将本地文件或在线资源解析为可读取的图片内容。
3. 按目标平台检查登录、转换格式、上传图片，并用目标地址替换正文引用。
4. 创建草稿，返回草稿链接，记录每个平台的成功或失败。
5. 让扩展界面和 MCP 复用同一套任务处理与平台适配器。

公开资料没有说明具体上传接口、签名实现、图片去重、重试退避或各平台是否通过页面脚本执行请求。因此这些细节仍需从目标平台的实际行为独立验证，不应据产品宣传猜定实现。

## 对当前问题的应用

本次复现表明，yuzgeo 的平台列表为空来自消息来源校验：扩展页面在浏览器标签页中打开时也携带 `sender.tab`，旧实现错误拒绝了这类消息。现在通过扩展 ID 与扩展页面 URL 校验来源，仍拒绝网站内容脚本。

正文预览中，DOM 读取成功不能证明用户能看到内容：旧 iframe 在实际截图中仍是白板。预览已改为页面内的 DOMPurify 过滤 HTML；本地图片使用 data URL。正文先显示，不等待图片检查或图片读取；空文件、读取失败和后台无响应均给出提示，并提供 Markdown 原文入口。

用独立 Chromium 内核浏览器加载真实构建产物，验证单文件导入、空文件、图片缺失、图片读取挂起或失败、目录图文导入和危险 HTML 过滤。平台登录接口在测试中使用固定响应，未验证真实账号上传或创建草稿。
